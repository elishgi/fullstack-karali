+תיאור פרויקט: Karali Events Tracker
+=================================
+
+תקציר מנהלים
+-------------
+Karali היא מערכת חוצת פלטפורמות לניהול ומעקב אחרי "אירועים" אישיים – פעולות, הרגלים, משימות או מדדים – המשלבת אפליקציית מובייל מבוססת React Native עם שרת Node.js ו-MongoDB. המערכת מאפשרת למשתמשים ליצור אירועים, לתעד כל לחיצה או פעולה, לצרף תמונות ומיקומים, לעקוב אחרי התקדמות לאורך זמן ולהפיק תובנות וייצוא נתונים. החזון הוא להפוך התנהלות יומיומית למשהו מדיד, מתועד ומשותף, תוך שמירה על חוויית משתמש חמימה ושיתופית.
+
+חזון ומטרות מוצר
+-----------------
+* **לייצר מודעות לפעולות יומיומיות** – המשתמשים לוחצים על אירועים (כפתורים) כדי לספור הישגים, התמדה או התרחשות של אירוע מסוים.
+* **לאפשר תיעוד עשיר לכל אירוע** – כל לחיצה יכולה להתלוות לתיעוד מפורט, תמונה, מיקום והערה, כך שניתן לחזור אחורה ולהבין את ההקשר.
+* **לחזק שיתוף וקהילתיות** – אירועים יכולים להיות משותפים עם חברים או בני משפחה (Shared Events), כך שניתן לתאם מעקב משותף.
+* **לתמוך באירועים זמניים** – אירועים בעלי תוקף (לדוגמה: אתגר של שבוע) מתנהלים עם מנגנון תפוגה, תזכורות ותיעוד מתקדם, כולל ייצוא CSV לסיכום.
+* **להעניק חוויית משתמש מלאה במובייל** – מרגע ההרשמה, דרך מסך הבית ועד לניהול חשבון, הכול מתוכנן עבור מכשירים ניידים, עם תמיכה בהודעות, אחסון מקומי וניווט אינטואיטיבי.
+
+מבנה כללי של הפרויקט
+---------------------
+```
+fullstack-karali/
+├── client/   # אפליקציית React Native (Expo)
+│   ├── src/
+│   │   ├── screens/        # מסכי אפליקציה (Home, Logs, AddEvent, Login ועוד)
+│   │   ├── components/     # רכיבים חוזרים (כפתורי אירועים, סרגלי פעולה, מודלים)
+│   │   ├── navigation/     # הגדרת הניווט (React Navigation)
+│   │   ├── services/       # לקוח Axios לתקשורת עם ה-API
+│   │   └── utils/          # ניהול התראות מקומיות ב-AsyncStorage
+│   └── App.js, index.js    # נקודת כניסה ועטיפה של הנווט
+├── server/   # שרת Express
+│   ├── controllers/        # לוגיקת API עבור משתמשים, אירועים ולוגים
+│   ├── routes/             # קובצי ניתוב REST
+│   ├── models/             # סכמות Mongoose ל-User, Event, Log
+│   ├── middleware/         # אימות JWT
+│   └── app.js              # הגדרות אפליקציית Express וחיבור ל-MongoDB
+└── קבצי תיעוד ותמיכה נוספים (חזון, הצעות לשיפור ועוד)
+```
+
+הצד הלקוח (Client)
+-------------------
+* **טכנולוגיה:** React Native עם Expo, ניווט באמצעות `@react-navigation/native`, וניהול מצבים מקומיים באמצעות Hooks.
+* **מסכי מפתח:**
+  * `LoginScreen` ו-`SignUpScreen` – הרשמה והתחברות מאובטחת באמצעות JWT.
+  * `HomeScreen` – ליבה של האפליקציה, מציגה רשימת אירועים ככפתורים צבעוניים. כל לחיצה יוצרת תיעוד חדש, מעדכנת מונים ומציגה מידע משלים (זמן אחרון, התראות תפוגה, סטטוס ארכוב).
+  * `AddEventScreen` – טופס יצירת אירוע עם בחירת צבע, קביעת סטטוס זמני/קבוע, תאריך תפוגה ואפשרות לשיתוף עם חברים.
+  * `AddDetailedLogScreen` – הוספת תיעוד עשיר: הערות, צילום תמונה, בחירת או צילום מיקום (MapView), הפקת כתובת בשיטה הפוכה ותיעוד האירוע בשרת.
+  * `LogsScreen` – רשימת לוגים ניתנת לסינון לפי טווחי תאריכים, חלקי יום, שם אירוע ועוד.
+* **רכיבים ייחודיים:** מודאל בחירת צבע, סרגלי מיון וסינון, סיידבר משתמש, ניהול התראות מקומיות (`notifications.js`) עם ספירת הודעות שלא נקראו, ותמיכה מלאה בעברית (RTL, תאריכים ותוויות מקומיות).
+* **אינטראקציה מול ה-API:** קובץ `services/api.js` מגדיר מחלקת Axios שמזריקה טוקן JWT לכל בקשה, ומתממשקת לנתיבי REST ליצירת אירועים, תיעוד, ייצוא סיכומים, ניהול חשבון ועוד.
+
+הצד השרת (Server)
+------------------
+* **טכנולוגיה:** Node.js עם Express, מסדי נתונים MongoDB דרך Mongoose, אימות באמצעות JWT, ומידלוור CORS ו-JSON.
+* **מנגנוני אבטחה:**
+  * `middleware/auth.js` מאמת טוקנים (`Authorization: Bearer`) או פרמטר `token` בשורת הבקשה.
+  * משתמשים חדשים נרשמים עם סיסמאות מוצפנות (`bcrypt`) ומקבלים טוקן חתום.
+* **סכמות נתונים:**
+  * `User` – מזהה ייחודי, שם משתמש, פרטי התקשרות, ביוגרפיה קצרה ושדות מטא (timestamps).
+  * `Event` – פרטי האירוע (שם, צבע, סטטוס שיתוף, משתתפים, סוג קבוע/זמני, זמני תפוגה, סטטוס ארכוב, לחיצה אחרונה ועוד).
+  * `Log` – תיעוד פעולה עם שיוך לאירוע ולמשתמש, חותמות זמן, חלק ביום, יום בשבוע, מיקום, תמונה והערות.
+* **בקרי API:**
+  * `user.controller.js` – הרשמה, התחברות, עדכון פרופיל, איפוס חשבון (מחיקת אירועים ולוגים), מחיקת משתמש.
+  * `event.controller.js` – CRUD מלא, ניהול תפוגות, איפוס אירועים, ארכוב, הפקת סיכומים, ייצוא CSV לאירועים זמניים ומעקב אחרי תיעודים.
+  * `log.controller.js` – יצירה, שליפה (עם סינונים גמישים) ומחיקה של תיעודים.
+* **ניתוב (Routes):** מאוגד בקבצים (`user.routes.js`, `event.routes.js`, `log.routes.js`) תחת `/api/users`, `/api/events`, `/api/logs` ומוגן ב-auth middleware היכן שצריך.
+
+חוויית המשתמש והפיצ'רים המרכזיים
+----------------------------------
+1. **ספירת אירועים בלחיצת כפתור:** כל אירוע מוצג ככפתור גדול וצבעוני. לחיצה מעדכנת את המונה, שומרת את זמן הלחיצה האחרון ומייצרת תיעוד בלוגים.
+2. **ניהול אירועים זמניים:** ניתן להגדיר זמן תפוגה או משך (במילישניות). המערכת מחשבת ספירת לאחור, מזהה אירועים שפג תוקפם, מאפשרת לסמן התראה נשלחה, ולאתחל אירועים עם מחיקת לוגים או בלעדיה.
+3. **תיעוד עשיר:** כל לוג כולל חלוקה לחלקי היום, יום בשבוע, הערות, תמונות ומיקום גיאוגרפי. ניתן לפתוח מפה, לבחור נקודה ולהפוך אותה לכתובת קריאה.
+4. **התראות פנימיות:** שימוש ב-AsyncStorage ליצירת "התראות" שמופיעות בתוך האפליקציה (לדוגמה, אירוע ראשון שנוצר, יצירת אירוע משותף ועוד) עם ניהול מצב קריאה.
+5. **סיכומי אירועים והפקת דוחות:** המערכת מחשבת נתונים מצטברים (מספר תיעודים, חלוקה לחלקי היום, התיעוד הראשון והאחרון) ומייצרת קבצי CSV באירועים זמניים.
+6. **ממשק בעברית מלאה:** החל ממחרוזות הממשק ועד פורמט התאריכים, הכול מותאם לקהל משתמשים דובר עברית.
+7. **ניהול חשבון משתמש:** עדכון פרטים אישיים, איפוס מלא של המידע או מחיקת החשבון כולו.
+
+זרימת הנתונים בין הלקוח לשרת
+-----------------------------
+1. המשתמש מתחבר → הלקוח שומר טוקן JWT ב-AsyncStorage.
+2. כל בקשה ל-API מעבירה את הטוקן בכותרת Authorization.
+3. השרת מאמת את המשתמש, דואג שכל נתון מסונן לפי `userId`, ומחזיר JSON.
+4. הלקוח מציג את המידע, מאפשר אינטראקציה (יצירת אירוע/לוג, עריכה, מחיקה) ומסתנכרן בזמן אמת עם ההחזר מהשרת.
+5. מידע משלים (התראות, מצב סינון, ערכים מחושבים) נשמר באופן מקומי או מחושב בצד הלקוח עבור חוויית שימוש מהירה.
+
+הנחיות התקנה והרצה
+-------------------
+1. **שרת:**
+   * `cd server`
+   * `npm install`
+   * הגדרת משתני סביבה בקובץ `.env` (MONGO_URL, JWT_SECRET, PORT).
+   * `npm start`
+2. **לקוח:**
+   * `cd client`
+   * `npm install`
+   * יצירת קובץ `.env` עם `EXPO_PUBLIC_API_URL` לכתובת השרת.
+   * `npx expo start` (או `npm start`) והפעלת האפליקציה בסימולטור / מכשיר אמיתי.
+
+הזדמנויות להמשך פיתוח (Roadmap)
+---------------------------------
+* **אינטגרציית Push Notifications** חיצונית (Expo Notifications) להתרעות על אירועים שעומדים לפוג.
+* **חיזוק אירועים משותפים:** סנכרון בזמן אמת, הרשאות לכל משתתף, תצוגת סטטיסטיקות קבוצתית.
+* **Analytics מתקדם:** לוחות מחוונים, חישובי מגמות, המלצות ליעדים עתידיים.
+* **מצב Offline-first:** קאשינג לוגים ואירועים והשוואתם מול השרת בעת חזרה לרשת.
+* **אבטחה והקשחה:** אימות דו-שלבי, מגבלות קצב, תיעוד אבטחה ו-logging בצד השרת.
